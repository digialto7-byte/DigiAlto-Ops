## 4. Page transitions (cross-document View Transitions)
`@view-transition{navigation:auto}` in `motion.css` inside `@media (prefers-reduced-motion:no-preference)` is safe as a progressive enhancement (Chrome and Safari 18.2+ support it; Firefox ignores it, nothing breaks) if scoped:
- Intros: gate (home, key `g`), book (menu, `m`), pour (wine list, `v`) are decided before first paint by the head script (`intro-done` class) and `main.js` plays them over a fixed overlay (z-index 2000). A crossfade into a page that is about to start an intro would show the old page, then the new page's first frame, then the intro. So in a `pagereveal` listener (in `main.js`, not inline) call `event.viewTransition.skipTransition()` when `html` lacks `intro-done` (the intro will play), and also when the target has a hash or the language twin is opened (IT/EN switch: change of language is not a page change). Use `pageswap` to skip when leaving to a page that will play an intro (home to menu first time). Never animate anything in the hero (it must be painted from first paint): do not give the hero or `h1` a `view-transition-name`.
- Things that can go wrong: the new page is held until its render-blocking CSS (`styles.css`, `motion.css`) arrives (browser limit about 4 s): it is only a delay on warm cache; the site has no blocking fonts (fonts.css is `media=print` first), good. Names must be unique per page: only `site-header` (fixed, solid or transparent: its state flips on scroll, so snapshot looks wrong mid-page: use `view-transition-name:none` on `.site-header` and let it crossfade with the root instead) and `.cta-bar`. Elements hidden by start states (`[data-reveal]` at opacity 0) are captured hidden: the new page shows its content only after it builds, so keep the transition short (200 to 250 ms, root crossfade only, no names on content). Lenis: nothing to do, it starts on `DOMContentLoaded`. Lighthouse does a cold load, so the score is not touched.
- Scope: only the root crossfade plus `::view-transition-old(root)/new(root){animation-duration:.22s}`; `@media (prefers-reduced-motion:reduce)` gets no `@view-transition` rule at all. Name the logo only if the motion specialist wants it. Test: home to menu (intro plays, transition skipped), menu to wine list, language switch, back button (bfcache keeps working: do not add `unload`).

## 5. Icons
- Today: `{{svg:name|attrs}}` in templates reads `assets/<name>.svg`, strips the XML prolog, adds attributes to the `<svg>` tag (`build_pages.py` line 219). Line icons are 64×64, `fill:none`, `stroke:currentColor`, `stroke-width:1.25`, round caps, with a `<title>` (e.g. "Vino": a hover tooltip even when `aria-hidden`; strip titles of decorative icons in `svg()` or keep them for IT only). CSS: `.icon` 44 px, `.icon--large` 4.5 rem gold, `.icon--deco` (lines 332 to 334); the pages use six of them. The draw-on hook: `data-draw` on the `<svg>` (`setupDrawing`, `main.js` line 897): every `path/line/polyline/circle...` with a stroke is dashed and drawn over 0.9 s when the element reaches 80% of the viewport; shapes that cannot be dashed fade in; reduced motion and no-JS show it complete.
- Cheapest correct way to add about eight icons: (1) draw the seven spare SVGs plus one or two new ones in the same grid (they exist; add `merlatura`, `icon-volta` etc.), 10 to 20 paths each, so no new JS; (2) put them in templates as `{{svg:icon-pici|class="icon icon--large" aria-hidden="true" focusable="false" data-draw}}`; (3) one small CSS pattern: `.icon-row` (flex, gap) for a row of three icons with labels, `.icon--stroke-sync` nothing needed. Each icon costs about 0.5 KB of HTML per page and per language; eight icons add about 8 KB to each home page uncompressed, 3 KB gzip. Do not use an SVG sprite with `<use>`: the draw routine measures path lengths in the document and cannot read shadow-tree content.
- Do not add `data-draw` to more than about 10 icons per page: each is one ScrollTrigger plus a computed-style read in `strokeLength`.
